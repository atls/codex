# Model Fit hook в Codex Desktop

## Область включения

Автоматический режим включается для одного выбранного треда в одном проекте.
Сначала установи пакет в устойчивый каталог, затем выполни
`scripts/configure.py --project <project-root> --thread-id <thread-id> --write`
из установленной копии. Утилита добавляет `UserPromptSubmit`, `PreToolUse` и
`Stop` в `<project-root>/.codex/hooks.json`, сохраняя чужие обработчики.
В Git-репозитории она добавляет этот локальный файл в `info/exclude` и откажется
записать личный ID треда в уже отслеживаемый `hooks.json`. Без `--write`
команда только показывает действие. Рабочая команда hook указывает на тот же
устойчивый каталог, из которого запущена утилита, а не на временный worktree.

Codex требует доверить точные новые определения через `/hooks`; проверь их
через `hooks/list`. Уже загруженная сессия может сохранить старые определения:
при смене пути дождись завершения активного хода и обнови сессию штатным
механизмом Codex. Не прерывай работающий ход ради установки. Для выключения
выполни ту же утилиту с `--remove --write` и перечитай `hooks/list`.

`~/.codex/hooks.json` для этого пакета не меняется. Обработчик до любой triage
проверяет точный `session_id` из локального определения и пропускает другие
треды проекта без чтения их запросов и состояния.

## Автоматический перенос в следующий ход

`UserPromptSubmit` получает текущую model из события, reasoning из
`thread/read` и запускает `scripts/triage.py`. При `keep` запрос выполняется
обычно; при `unknown` пригодность профиля остаётся непроверенной. Уточнения
внутри уже допущенного хода с тем же `turn_id` не запускают повторный triage.

При обоснованной смене model или effort исходный ход становится техническим.
Агент вызывает `mcp__codex_app__send_message_to_thread` для этого треда с
целевым профилем, затем точную команду `queue`, полученную от hook. Утилита
читает полный `userMessage.content` через `thread/items/list`, добавляет
одноразовую метку и ставит нативный ввод в `thread/queue/add`. Ответ очереди
проверяется по порядку и содержанию элементов; нативное преобразование
`localImage` в `image` принимается только при сохранении остальных полей.
Исходный запрос автоматически выполняется следующим ходом на целевом профиле.
Пользователь отправляет его один раз.

`PreToolUse` оставляет техническому ходу только смену профиля и постановку
очереди. Для хода с подтверждённым `passed` он пропускает инструменты и при
кратковременно занятом lock. `Stop` отдельно проверяет релевантность только
подтверждённого текстового replay; вложения и уточнения внутри replay не
переносятся на модельный оценщик. Эта проверка добавляет отдельный модельный
прогон и время к текстовому продолжению.

## Состояние и диагностика

Локальное состояние хранится в `CODEX_HOME/.tmp/model-fit-auto-switch/`, audit —
в `CODEX_HOME/.tmp/model-fit-hook-audit/`. Audit записывает исход, ID хода,
время, фазу и код причины; при занятом lock — доступные PID, операцию и ID хода
владельца. Текст запросов, аргументы инструментов и вложения в audit не
попадают. Если запись audit недоступна, обработчик сообщает тип ошибки в
stderr. Не считай отсутствие строки доказательством отсутствия сбоя.

Состояние `attempting` фиксируется до вызова очереди: при неизвестном исходе
утилита не повторяет постановку, чтобы не создать дубль. Подтверждённый отказ
очереди сохраняет `rejected`. При следующем отдельном пользовательском ходе
hook проверяет состояние нативной очереди и исходного продолжения перед новым
triage. Настройка модели в UI сама по себе не доказывает модель фактического
исполнения; проверяй ходы и доступные native execution traces.

Пакет проверен для Codex Desktop на macOS. Для автообновления профиля требуется
доступный агенту `mcp__codex_app__send_message_to_thread`; установку и
поведение на другом runtime проверяй отдельно. Установленный plugin не
подключает project-local hooks автоматически и не получает доверие без `/hooks`.
